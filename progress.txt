## Codebase Patterns
- Contracts live in ../koine (KINP/KGP/KCB/KMI/KCS + ADR-0001). Implement against them; do not
  re-specify.
- ADR-0001 invariants: registry routes by lookup (returns addresses, never proxies traffic);
  the console observes REAL direct connections; provider-router (model backends) and
  inter-platform routing are distinct concerns. These are encoded as assertions
  (`describeRegistry().proxiesTraffic === false`), not just prose — don't relax them to make a
  test pass.
- Two toolchains, one gate: `make check` runs everything; `make check-<area>` runs one.
  Deps install themselves. See CLAUDE.md "Quality gates".
- TS is a **source-first** npm workspace: root package.json holds the shared devDeps, each
  package's `exports` points at `src/index.ts`, `tsc` emits nothing — so no cross-package build
  ordering. Relative imports carry the real `.ts`/`.tsx` extension.
- The Python tools read config from `provider-router/pyproject.toml`, so the Makefile runs them
  as `cd provider-router && uv run …`; `uv --project … run mypy` silently loses the config.
- The koine spec versions are pinned in BOTH `schemas/src/versions.ts` and
  `agora_provider_router.KCB_VERSION`, and a pytest cross-asserts them. Bump both together.
- Secrets are `SecretStr` and nothing retains the raw environment — a config that does puts
  every exported key into its own `repr`. Anything reportable goes through a `describe()`
  that reports *whether* a key is set, never its value; tests assert on the rendered surface.
- FastAPI routes take their dependencies as `Annotated[T, Depends(fn)]` module-level aliases
  (a call in an argument default trips ruff B008), and `app.dependency_overrides` keys on the
  `fn` identity — which is how a test swaps the whole router for one it configured.
- **Every router knob goes under `AGORA_*`.** `RouterConfig.env` retains only that prefix (so no
  repr can leak a secret), which means a new variable named that way arrives at the ladder, the
  cost table and the manifest with no plumbing — `AGORA_PRICE_*`, `AGORA_PUBLIC_BASE_URL`.
- **Safety invariants are asserted on what was CONTACTED, not on what won.** `recording_transport`
  records every backend the transport was handed; zero-spend and budget tests assert that list is
  empty. "It lost the race" is not the same guarantee as "it was never dialed".
- **Cross-language pins make file paths API.** The spec versions now live in
  `schemas/src/versions.ts` and the router's zero-spend manifest is captured at
  `registry/src/fixtures/provider-router.manifest.json`; pytest reads BOTH by path. Moving or
  regenerating either is a two-language edit. Regenerate the fixture with the command in the
  test's failure message; never hand-edit it.
- **Unpriced is not free, anywhere in the stack.** The router flags a cost it could not compute,
  and both `find` and `path` rank those last however expensive the priced alternative is. A
  missing price read as 0 makes the unknown route the system's favourite.
- **Under `mypy --strict`, a helper taking `**env: str` plus another parameter needs that
  parameter positional-only** (`def f(calls, ceiling, /, **env: str)`) — the splat could otherwise
  supply it. Splitting into two helpers (conftest's `router_for`) is the other way out.

## US-AG2 — Provider-router: the sacred ladder, OpenAI-compatible, always-completes
- New modules under `provider-router/src/agora_provider_router/`: `ladder.py` (tier order as
  configuration), `backends.py` (tier → dialable backend or the reason it is not),
  `placeholder.py` (the deterministic terminal tier), `router.py` (the walk + the invariant),
  `config.py` (the CUNEIFORM_PROVIDER_* schema); `app.py` grew the OpenAI routes and /doctor.
- Tests: `test_ladder.py`, `test_config.py`, `test_fallthrough.py`, `test_zero_spend.py`,
  `test_app.py` + `conftest.py` (43 passing). Gate `make check-provider-router` green.
- Ported from Analyzer with two deliberate changes: ladder tokens are the four TIERS
  (paid/mlx/local + terminal placeholder) rather than vendor names, because here the router
  *is* the ladder; and the local tiers require a CONFIGURED base URL — no implicit localhost
  probe, or "no local servers" would depend on what happens to be listening on the box.
- Next: US-AG3 — budget ceilings + the KCB manifest. The upstream cost logic is in
  its `core/cost.py` / `cost_gate.py`. Seams already in place:
  `Backend`/`TierResolution` are where a per-capability `cost` hangs, `Completion.routing()`
  is where projected/actual cost joins the response, and the placeholder already reports
  zero-token usage so an estimator can read every tier the same way.

### Learnings for future iterations
- **A config must not retain the environment.** `RouterConfig` first kept the whole env dict
  for ladder lookups; a `repr` of it then contained every exported key and the secrets test
  caught it. It now keeps only `AGORA_*`. Keys are `SecretStr` everywhere, and failure
  reasons redact the backend's own key (a transport error quotes the URL it dialed).
- **`next(gen)` on a `@contextmanager`-shaped generator is a trap.** `client = next(client_for(r))`
  left no reference to the generator, so it was collected immediately, its `finally` ran, and
  the FastAPI dependency override was cleared before the request — two tests silently
  exercised the real environment instead. Use a plain function + an autouse cleanup fixture.
- **FastAPI + ruff:** `Depends(...)`/`Body(...)` in an argument default trips B008. Use
  `Annotated[Router, Depends(get_router)]` aliases — and keep `Depends(get_router)` by name,
  since that identity is what `app.dependency_overrides` keys on.
- **A test helper taking both `**env` and a named option does not type-check** under
  `mypy --strict`: unpacking a `dict[str, str]` could supply that option. Split them —
  `router_for(**env)` for the common case, `Router(config_for(**env), transport)` when a test
  needs a fake transport.
- Tests import `conftest` directly (`from conftest import ...`); pytest puts `tests/` on the
  path and mypy resolves it, so shared helpers do not need a package.
- The `agora` key on every generation response (tier/provider/model/attempts, mirrored into
  `X-Agora-*`) is the seam the console (US-AG5) reads. Body over header on purpose: a header
  needs CORS expose-headers to survive a browser fetch.

## US-AG3 — Cost/budget enforcement + the router's KCB capability manifest
- New `provider-router/src/agora_provider_router/cost.py` — pure pricing: `measure` (size a
  request per modality), `rate_for` (per-(modality, provider) table + `AGORA_PRICE_*` override),
  `project` (before dispatch) / `settle` (against the response), `take_ceiling`/`parse_ceiling`,
  `within`/`refusal`. New `manifest.py` — the KCB §2 manifest, at `/.well-known/kcb-manifest.json`.
- `router.py`: the walk is budget-gated; `Attempt` gained `dialed`, `Completion` gained
  `projected`/`actual`/`budget_units` and a `cost()` block on `routing()`. `backends.py`:
  `resolve_tier(..., rank)` — `_resolve_paid` collects ALL usable vendors and picks
  `min(ready, key=rank)` when ranking, first-declared otherwise. `app.py`: the
  `X-Agora-Budget-Units` request header, an `X-Agora-Cost-Units` response header, the manifest
  route, and a 422 on an unreadable ceiling.
- Tests: `test_cost.py`, `test_budget.py`, `test_manifest.py` + HTTP coverage in `test_app.py`
  (109 passing). `make check` exit 0.
- **Ladder = preference, ceiling = constraint.** The AC says "prefers the lowest-cost satisfying
  tier", but sorting the whole ladder by cost would send EVERY budgeted request straight to the
  free placeholder and delete the sacred ladder. So rungs are walked in ladder order and one
  projected over budget is pruned; because the ladder runs expensive→free, the first survivor IS
  the best affordable rung. Cheapest-wins applies only where the ladder expresses no preference —
  between two usable paid vendors (`rank`).
- **Costs are KCB budget units, not USD** (anchored 1 unit = US$0.00001): a grant crosses projects
  that share no billing account, so the bus needs one comparable scalar. Rates ported from the
  upstream USD table, which lives at its `cost.py` — NOT `core/cost.py`, as US-AG2's
  note said. `unpriced` is deliberately not `free`: an unknown vendor prices 0.0 but is flagged,
  and `within()` refuses it under any ceiling, or it would become the ladder's cheapest route.
- **The manifest advertises the CURRENTLY RESOLVED tier's cost**, so a keyless router publishes
  `tier=placeholder, est_units=0`. A static price list would make the registry's zero-cost
  preference (KCB §3) wrong precisely on zero-spend deployments. Priced against a fixed nominal
  request per modality (`NOMINAL`), published as `cost.basis`, so figures are comparable.
- **No endpoint is advertised that is not served** — no `mcp`/`a2a` keys until they exist, because
  a manifest address is a promise the registry hands to peers who dial it DIRECTLY (ADR-0001
  decision 3). `test_manifest.py` pins the endpoint key set, so a future story must add the server
  and the advertisement together.
- Next: US-AG4 — the registry indexes this manifest. It is served at
  `/.well-known/kcb-manifest.json` and `manifest.capability_manifest()` builds it; the TS side has
  no manifest type yet, so US-AG4 will want one in `schemas/`.

### Learnings for future iterations
- **Assert on "was it dialed", not "did it win".** Spend happens at the connection, so
  `recording_transport`'s `calls` list is the real budget assertion; `completion.tier` alone would
  pass even if the paid rung had been contacted and merely lost.
- The `**env` + named-option mypy trap (US-AG2's note) bites again in test helpers. The fix that
  keeps call sites readable is a **positional-only** parameter:
  `def complete_with(calls, ceiling, /, **env: str)`.
- Derive test constants from the code under test (`PAID_UNITS = project(...).units`), not
  arithmetic on the rate table — `round(rate*qty, 6)` != `rate*qty` in float, and `measure("text")`
  adds prompt chars/3.5 on top of `max_tokens`.
- Editing `tasks/chief/*.json` with `json.dump` reformats the whole file (escapes em-dashes,
  re-wraps arrays). Flip `"passes"` with a surgical string edit instead.

## US-AG4 — Thin discovery registry: route-by-lookup, never proxy
- New `registry/src/`: `registry.ts` (the index + `find`), `path.ts` (capability-path search),
  `ports.ts` (`matchesPort` / `servesWorld` / `satisfies`), `cost.ts` (the ranking),
  `crawl.ts` (pull population + `registerProviderRouter`), `fixtures/` (synthetic providers +
  the router's captured manifest). `schemas/` split into `versions.ts` / `planes.ts` /
  `identity.ts` / `manifest.ts` with `index.ts` re-exporting. `clients/kcb-client` gained
  `addressOf` / `endpointFor` and an open endpoints map. `resolver/` gained the interface stub.
- Tests: 51 in registry, 16 in schemas, 5 each in clients/resolver, +1 pytest. `make check` exit 0.
- **The registry's surface is asserted, not just documented.** `describeRegistry().verbs` is
  compared against the prototype's own method names, so adding an `invoke`/`proxy` method fails
  the gate. Prose saying "never proxies" is what every proxy's README said first.
- **`find` splits into two questions and so does the code.** `matchesPort` (does this port
  answer the query) and `satisfies` (can this produced port feed that consumed port) look
  similar and are not: the second is asymmetric — the consumer states requirements, the
  producer meets the ones stated. Conflating them made path search accept backwards hops.
- **Unpriced is not free** (carried over from US-AG3's `cost.unpriced`). Both `find` and `path`
  rank unpriced last however expensive the alternative; reading a missing price as 0 would make
  the *unknown* route the registry's favourite, which is the opposite of KCB §3 delta K.
  A capability with no `cost` block at all is unpriced too — absence is not zero.
- **Ladder-style preference vs. constraint, again.** Path search is best-first on
  (unpriced hops, projected units, hop count) — not shortest-path — because §3 says "prefers
  zero-cost routes"; a shorter paid path losing to a longer free one is the intent.
- **A world query is refused, not guessed.** A media port with no `world_pattern` does not
  answer `find({world})`. Delta J exists because world-scoped discovery is impossible without
  the declaration; defaulting to "probably all worlds" hands back a provider that may hold
  none of that world's material. But `satisfies` only constrains worlds when BOTH ends declare
  one — mid-chain, an unscoped producer is unscoped material, not wrong-world material.
- The provider-router is the first entry, crawled from `/.well-known/kcb-manifest.json`.
  `registry/src/fixtures/provider-router.manifest.json` is the real zero-spend manifest captured
  verbatim, and `provider-router/tests/test_manifest.py::TestTheRegistryFixture` asserts the
  capture is still current — the same cross-language pin as the KCB version, one level up.
  The failure message carries the regeneration command; regenerate, never hand-edit.
- Next: US-AG5 — the console. Seams in place: `registerProviderRouter(registry, baseUrl, {fetch})`
  takes an injectable fetch (so the console can instrument the traffic it observes),
  `find({capability:'generate.text'})[0].capabilities[0].endpoint` is the exact URL to POST to,
  and the response's `agora` block (US-AG2) carries the tier/cost to surface. `createLocalResolver()`
  is the resolver the console depends on; `describeResolver().implemented === false` on purpose.

### Learnings for future iterations
- **Split a package into modules before it needs re-exporting, not after.** `schemas/index.ts`
  held the spec-version pin that a *pytest* greps by path; moving it to `versions.ts` meant
  editing `test_skeleton.py` in the same commit. Cross-language pins make file paths API.
- **`as const` on a port literal breaks assignability**: `readonly ['audio/wav']` is not
  `string[]`. Annotate test fixtures with their real type (`const MIDI: MediaPort = …`) instead.
- **Avoid a runtime import cycle by extracting the shared leaf.** `path.ts` needed `costOf` from
  `registry.ts`, which imports `path.ts`; `cost.ts` broke it. Type-only imports (`import type
  { Registration }`) are erased and stay fine either way.
- `@typescript-eslint/recommended` bans `!`, so narrow into a local (`const { mediaType } = query`)
  before using an optional field inside a closure — property narrowing does not survive a callback.
- `structuredClone` is not in the `ES2023` lib the repo pins. A manifest is JSON by definition, so
  `JSON.parse(JSON.stringify(x))` is both available and honest about what is being copied.
- Frozen objects: assigning to one throws only in strict mode — which ESM always is, so
  `expect(() => { frozen.x = 1 }).toThrow()` is a valid assertion in vitest.

## US-CS7 — Live fabric monitor: passive, cross-platform event feed
- New `console/src/monitor/`: `monitor.ts` (the passive watch — sources, `sweep()`, `events()`,
  `describeMonitor()`), `feed.ts` (the log projected into filterable `FabricEvent` rows),
  `Monitor.tsx` (the panel). New `console/src/kcs/spans.ts` — the control-plane counterpart to
  `facts.ts`. `Observation.span` + `planeOfFrame` in `kcs/log.ts` / `kcs/link.ts` /
  `kcs/standin.ts`; `observeCommons` in `commons.ts`; a third `monitor` mode in `App.tsx`;
  fixtures `console/src/fixtures/monitor/{analyzer,insimul}.json`.
- Tests: `spans.test.ts` (8), `feed.test.ts` (11), `monitor.test.ts` (15), +5 in `App.test.tsx`.
  `make check` exit 0 (191 console tests).
- **What ADR-0001 lets a passive observer do is the whole design.** Decision 7 permits
  subscribing; it forbids reading the wire between two other peers, because that IS the
  payload-aware proxy. So the data plane is complete today (every delta/media event a producer
  publishes reaches the feed, whoever triggered the work) and the control plane is visible only
  where a provider EMITS a record of its own exchanges. A provider that emits none is absent at
  the invoke level — stated per source on screen, in `describeMonitor().limitation`, and in both
  READMEs. A monitor that quietly showed an empty invoke view would read as "no invocations
  happened" when it means "nobody emitted telemetry".
- **`kcs/spans.ts` is deliberately provisional and narrow.** koine has no emitted-telemetry
  contract (KCB §4 fixes five verbs and nothing about observability), so the recognition rule is
  "a frame is telemetry only when it SAYS it is" (`kind: exchange`, or a `span`/`exchange`
  envelope) and it must name a `verb` or a `capability`. Inferring spans from delta shapes would
  have the monitor reporting exchanges nobody made. This is the one module that expects to be
  rewritten against a spec rather than to define one — the koine follow-up is a KCB observability
  extension fixing the span shape.
- **A span is `control`, not `knowledge`.** `Plane` is the KCB §2.1 *data*-plane vocabulary, so
  `planeOfFrame` returns `undefined` for a telemetry-only frame and the feed types the row
  `control`. Defaulting to `knowledge` (which the old inline expression did) would have filed
  every span under the knowledge plane and made the plane filter lie.
- **The monitor is configured with what to watch, not handed every fixture.** `monitorStandins()`
  is its own small map; subscribing to every bundled fixture with a `subscribe` section would
  watch the same peer three times over, once per scenario that recorded it. `monitor/analyzer.json`
  emits telemetry and `monitor/insimul.json` does not, so the documented limitation is
  demonstrated on screen rather than only asserted in prose.
- **The App keeps the monitor instance, not its snapshot.** The monitor owns the observation log,
  so sweeping again appends and the feed accumulates; storing a snapshot would have "sweep again"
  replace the feed with the last few seconds of it, and `since` would filter against the last
  button press rather than real elapsed observation.

### Learnings for future iterations
- **Encode a topological invariant as an assertion on the code's own surface.** `monitor.test.ts`
  reads `Object.getOwnPropertyNames(FabricMonitor.prototype)` and fails if an `invoke`/`emit`/
  `relay` ever appears — the same shape as `describeRegistry().verbs` (US-AG4). Prose saying
  "passive" is what every proxy's README said first.
- **`worlds_pattern` is not a world.** KCB delta J patterns (`insimul:world:*`) cannot be expanded
  into a subscription target; `worldsIn()` collects concrete `worlds` off knowledge ports only,
  and a peer declaring none is subscribed to without a world filter (KCB §4's other form).
- Fixture map insertion order is the sweep order, and therefore the feed's. A test asserting the
  event sequence is asserting on `MONITORED`'s key order — assert on a `Set` of participants when
  order is not the point.
- `eventsFrom` reads only `direction: 'frame'` entries. That single line is what separates "the
  console's own traffic" (the timeline) from "what crossed the fabric" (the feed); widening it to
  responses would put every manual invoke into the passive feed.

## US-1 — Publish a coherent client SDK with a stable public API (@agora/sdk 0.1.0)
- `clients/kcb-client/` + `clients/relation-registry-client/` are now ONE package,
  `clients/sdk/` (`@agora/sdk`): `src/kcb.ts` (the address projection), `src/relation-registry.ts`
  (the registry loader), `src/index.ts` (the single published entry point, which also re-exports
  the AgentCard/manifest slice of `@agora/schemas` so the install really is one line).
  `registry/` and `console/` import `@agora/sdk`; `make check-clients` gates the one package.
- The surface documents itself: `SDK_API` (discover / participate / knowledge), `SDK_VERSION`,
  `describeSdk() → { version, specs, api, relaysPayloads: false }`. `src/index.test.ts` imports
  ONLY `@agora/sdk` (never a deep path), asserts the enumerated index equals the real runtime
  exports both ways, and fails on any relay-shaped export name.
- Publishing: `tsconfig.build.json` emits `dist/`; `scripts/stage-publish.mjs` assembles
  `<pkg>/.publish/` (dist + README + a derived package.json whose exports point at dist).
  `make build-sdk`, `make publish-dry-run`. `@agora/schemas` is published alongside it as the
  SDK's one dependency (0.1.0, no longer `private`).
- `make check` exit 0. Verified out-of-tree for real: `npm pack` the two staged dirs into a scratch
  consumer, `npm install` them, `node` runs a card→manifest→address round trip, and
  `tsc --module nodenext --moduleResolution nodenext` resolves the types.

### Learnings for future iterations
- **`publishConfig.exports` does not work.** npm 10.9 leaves `exports` untouched when it builds the
  tarball, so a package that develops from `src/` and ships `dist/` cannot switch entry points that
  way — the published package pointed consumers at `src/index.ts`, which is not even shipped
  (`ERR_MODULE_NOT_FOUND`). The fix is `scripts/stage-publish.mjs`: stage a derived package into
  `.publish/` rather than mutating package.json in place (a crash mid-publish would otherwise leave
  the workspace pointing at dist and break every in-tree import).
- **Prove out-of-tree resolution by leaving the tree.** `npm publish --dry-run` lists filenames and
  says nothing about whether `import '@agora/sdk'` resolves. Packing into a scratch dir, installing
  the tarball and running `node` is the only check that catches an `exports` map that points at
  files nobody shipped. Do the same for types with `tsc --moduleResolution nodenext`.
- **Emit is possible without giving up source-first.** `rewriteRelativeImportExtensions: true`
  (TS ≥5.7) lets the source keep the repo's real `./x.ts` specifiers AND emit runnable `./x.js`.
  A `tsconfig.build.json` extending the package's own tsconfig with `noEmit: false` + `rootDir`/
  `outDir` is all a publishable package needs. tsc copies no assets, though: `schemas/scripts/
  copy-schema-assets.mjs` puts `koine-schemas/*.json` beside the emitted `validator.js`, because
  that module resolves them off its OWN directory.
- **Node-only code must not sit on a package's main entry point.** `@agora/schemas`'s index
  re-exported the ajv validator, which imports `node:fs`/`node:path`; a bundler reports
  `"join" is not exported by "__vite-browser-external"` at LINK time — before tree-shaking can drop
  the unused module, and `sideEffects: false` does not help. It is now the `@agora/schemas/validator`
  subpath, and `version-drift.test.ts` asserts BOTH halves (the subpath exists in `exports`, and the
  index does not carry `validate`/`ARTIFACT_SCHEMAS`).
- **⚠️ `make build` is RED, and was before this story.** `npm run build -w @agora/console` fails:
  the console's browser bundle reaches Node-only modules through the `@agora/registry` index
  (`path-index.ts`, then `store.ts`/`server.ts`/`main.ts` behind it). `make check` never ran the
  bundle, so it rotted unnoticed. The SDK's publish path is `make build-sdk`, which does not depend
  on it. Fixing it properly means giving `@agora/registry` (and `@agora/resolver`) a Node-only
  subpath the way schemas now has — a story of its own, not a line in this one.
- `git grep`/`grep -r` SKIPS a file it decides is binary — `registry/src/path.ts` matched
  `@agora/kcb-client` and was reported only as "Binary file … matches", so a rename sweep missed
  it and the failure surfaced two builds later. Use `grep -a` when sweeping for a moved import.

## US-2 — A ~20-line participant starter that serves an AgentCard and answers on the wire
- New area `examples/participant-starter/` (`@agora/example-participant-starter`, private, a new
  `examples/*` workspace): `src/participant.ts` is the copy-and-run starter and `src/participant.test.ts`
  drives it over real HTTP. Gate `make check-examples`; it also runs inside `make check` (check-ts is
  `--workspaces`). README.md + CLAUDE.md layout tables list the area.
- The starter, above its "copy from here" divider (~22 lines of code): `participantManifest()` (KCB
  §2 — identity, endpoints, one plane-typed zero-cost capability), `participantCard()` = that manifest
  through `embedManifest`, `summarize()` (the peer's actual work, replaceable), and `handle()` — the
  three routes. Below the divider is the A2A/JSON plumbing an A2A server library would own, so the
  example's only dependency is `@agora/sdk` + Node.
- Three routes, because the fabric reads a peer two different ways: `/.well-known/agent-card.json`
  (the card, KCB manifest as its one extension), `/.well-known/kcb-manifest.json` (the BARE body —
  `registry.register` runs `parseManifestBody`, so a crawl that got a card would be rejected), and
  `POST /` (one A2A `message/send` → a completed Task). Sample data throughout: `example:agent:summarizer`
  / `summarize.text`, a made-up peer.
- The test is the acceptance criteria, end to end: start on an ephemeral port → GET the card →
  `parseManifest` from `@agora/schemas` → `addressOf`/`isDialable`/`transportOf`/`endpointFor` from the
  SDK → the console's own two-leg A2A dance (card GET, then `message/send` POST at `card.url`) → a
  completed task carrying the summary. A fifth test crawls the running starter with
  `registerFromWellKnown` and asserts `find({capability})` hands back its ADDRESS at `estUnits: 0`.
- `make check` exit 0; `make check-examples`, `make check-clients`, `make build-sdk` each exit 0.
  Verified by hand too: `PORT=8791 node src/participant.ts` + curl on all three routes.

### Learnings for future iterations
- **A TypeScript parameter property makes a package un-runnable by `node file.ts`.** Node 22's
  strip-only loader throws `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX` on `constructor(msg, readonly url: string)`
  — and because a workspace consumer resolves `@agora/sdk` to its SOURCE, one parameter property in
  `clients/sdk/src/relation-registry.ts` (`RegistryFetchError`) broke `node examples/.../participant.ts`
  entirely. Rewritten as a declared field + constructor assignment (same public shape). Out-of-tree
  consumers get `dist/` and never saw it, which is exactly why it went unnoticed. Same rule bans
  `enum` and `namespace` from the SDK's and schemas' source.
- **`registry.register` takes a manifest BODY, `parseManifest` takes a CARD.** `registerFromWellKnown`
  GETs `/.well-known/kcb-manifest.json` and runs `parseManifestBody`; the A2A card at
  `/.well-known/agent-card.json` carries the same body inside its extension. A participant that serves
  only the card is dialable but not crawlable — serve both, as the router and trainer do.
- **A card server should read its base URL off `req.headers.host`**, not off a configured port: the
  card then names the address the client actually dialed, so the same process is correct on an
  ephemeral test port, behind a proxy, and on its default port — and no `listen()` plumbing has to run
  before the card can be built.
- An example area is a workspace like any other: adding `examples/*` to the root `workspaces` puts it
  in `npm run lint/typecheck/test --workspaces`, so `make check` covers it without a new CI step.

## US-3 — Quickstart doc: install to first successful call
- `docs/quickstart.md`: three steps — install `@agora/sdk`, run the participant starter, make the
  first call — plus "Make it yours" (change `IDENTITY`/`CAPABILITY`/`summarize`, and the registry
  crawl that makes you findable) and a "Going deeper" fan-out to the walkthrough, the starter
  README, the SDK reference, prior-art and koine/KCB. It opens with **Addresses, not a relay**
  BEFORE the first command, so nobody reads the SDK as a switchboard.
- Every command and output in it was RUN, not written: the starter's three routes by curl on 8790,
  and step 3's `call-a-peer.mjs` in a scratch consumer outside the tree, against tarballs packed
  from `schemas/.publish` + `clients/sdk/.publish`.
- **The install step is honest.** `@agora/sdk` is NOT on npm (`npm view` → E404), so a doc whose
  first line was `npm install @agora/sdk` would fail a newcomer at step 1. The doc ships
  `make build-sdk` + `npm pack ./schemas/.publish ./clients/sdk/.publish` → install by path — the
  identical tarballs `npm publish` would send — and states that the same install collapses to one
  line once published, with nothing else in the guide changing. `clients/sdk/README.md` and
  `examples/participant-starter/README.md` now say the same thing beside their `npm install` line.
- `README.md` links it twice: at the top of "Getting started" and as the first entry under
  "Learn by example".
- `examples/participant-starter/src/quickstart.test.ts` (9 tests, runs under `make check-examples`)
  is the doc's gate: it reads `docs/quickstart.md` and re-derives the happy path from the code —
  the names it imports exist on `@agora/sdk`, the identity/capability/paths/spec version match the
  starter's constants, the printed answer equals `summarize(<the prompt the doc actually sends>)`,
  step 3's logged line equals `isDialable`/`transportOf`/`endpointFor` of the real manifest, the
  `.tgz` names carry the real package versions, every `make <target>` exists in the Makefile, every
  `node <path>` and relative link resolves on disk, and README links the doc.
- `make check` exit 0 (also `make check-examples` alone).

### Learnings for future iterations
- **A quickstart is a test fixture, not prose.** Doc drift is invisible until a newcomer hits it,
  so assert the doc against the code the way `index.test.ts` asserts `SDK_API` against the module:
  extract the doc's claims with regexes and re-derive each from the shipped exports. Guard every
  extraction loop with `expect(matches.length).toBeGreaterThan(0)` — a regex that stops matching
  after a doc edit otherwise turns the whole test vacuously green.
- **Check what a doc promises to install against what is actually installable.** `npm view <pkg>`
  is a one-line reality check; the tarball-name assertion (`agora-sdk-<version>.tgz` derived from
  `clients/sdk/package.json`) is what keeps the install step true across a version bump.
- The out-of-tree verification recipe from US-1 is now the doc's own Step 1, so it is exercised by
  a human every time someone follows the guide: `make build-sdk` → `npm pack <staged dirs>` →
  `npm install ./*.tgz` in a scratch consumer → `node` a script that imports only `@agora/sdk`.
- `npm pack` writes tarballs into the CWD, not beside the packed directory — the doc has to name
  the path they land at (the repo root) or the next command fails.

## US-1 (40-fabric-data-plane-bridges) — KGP knowledge sync: producer claims → a KGP consumer
- New TS area `knowledge/` (`@agora/knowledge`, workspace + `make check-knowledge`; listed in
  README "Components"/"Layout" and CLAUDE.md). The KGP data-plane bridge: `POST /claims` from ANY
  producer → admitted, packed, delivered to one KGP consumer → a receipt with graded rejections.
- `claim.ts` is KGP §3's byte discipline (the load-bearing part): `world|relation(args)`, symmetric
  operands sorted, CURIEs NFC + namespace/kind lowercased (local id opaque, provisional-local
  `ns:local:…` emitted as-is), typed literals per rule 5, `sha256-<hex>`. Everything §3.1 excludes
  (confidence, prov, license, egress, valid_time, embedding_model) really is excluded — a test
  asserts two producers' same fact mints ONE id (§3.3), which is the merge property.
- `admission.ts` grades every refusal with a code + the clause: unknown-relation (registry
  relations.tsv), arity-mismatch, malformed-argument/-world, local-only (§7.2), dialect-exceeded
  (§5), license-missing/-refused (§7.1), provenance-missing, untrusted-source,
  confidence-below-threshold, claim-id-mismatch. Reported, never silently dropped.
- `pack.ts` builds the §2 envelope + §2.1 content address (canonicalJson over manifest ⊕ the
  id-sorted record lists), files KINP's reserved relations under `links`, ledgers licenses in the
  manifest, and carries each record's exact `hash_input` so a consumer re-verifies with one SHA.
  Entities are NOT inlined — the bridge is a conduit with a gate, never a second knowledge store.
- `consumer.ts` projects a peer's KCB manifest → the knowledge-plane sink → its address, dialed
  direct. `main.ts` reads `AGORA_KNOWLEDGE_*` and refuses to boot with no consumer/registry.
- Also refreshed two DERIVED koine snapshots that had gone stale against koine:40, mechanically:
  `schemas/src/koine-schemas/` (`npm run -w @agora/schemas regen:koine-schemas`) and the trainer's
  vendored KFT schemas. **The trainer's drift test was RED before this story** — `make check` could
  not have passed on this branch without it.
- `make check` exit 0 (65 tests in the new area).

### Learnings for future iterations
- **The koine schema snapshot in `schemas/src/koine-schemas/` has NO drift gate.** The trainer's
  Python copy has `tests/test_schema_drift.py` and goes red; the TypeScript copy is only checked by
  `npm run -w @agora/schemas regen:koine-schemas:check`, which nothing in `make check` runs. So the
  TS validator can silently validate against a contract koine has moved past. Run the `:check`
  script by hand after any koine bump — or wire it into `check-schemas` (a story of its own).
- **⚠️ For US-2 (KFT):** koine's spec HEADERS now read KGP 0.5.0 / KFT 0.4.0 while koine's own
  `specs/README.md` index still says 0.4.0 / 0.3.0 — upstream is inconsistent, and agora pins the
  index's numbers in `schemas/src/versions.ts`. The refreshed `dataset-jsonl-header` schema adds
  `egress` and `recordCount` (file-level aggregates the §4.2 gate reads). Decide the version pin
  deliberately; bumping it is a three-language edit (TS `versions.ts`, Python `KCB_VERSION`, the
  Erlang conformance suite).
- **`exactOptionalPropertyTypes` shapes how you build optional fields**: `{...x, license: undefined}`
  is a type error, so a test that wants a field ABSENT constructs the literal without it, and
  production code spreads conditionally (`...(v === undefined ? {} : { k: v })`) — the idiom already
  all over the registry.
- **A `type` alias gets TypeScript's implicit index signature; an `interface` does not.** `GroundingPack`
  had to be a type alias to be passable to `@agora/schemas`'s `assertPackEgress` (which takes an open
  record). Making the shared §7.2 enforcement reachable beat the nominal shape.
- **`@typescript-eslint/no-unused-vars` as configured here does NOT honor rest siblings**: the
  `const { license: _license, ...rest } = x` omit-a-key idiom is an eslint error in this repo.

## US-2 — KFT dataset bridge: by-reference training-exhaust admission -> the trainer (40:US-2)
Built in `trainer/` (Python) rather than as a new TS area, because the §4 gate is NORMATIVE
*provider* behavior and the trainer's `admission.py`/`resolve.py` were blind to KFT 0.4.0's
`dataset.records[]` slot entirely — a TS bridge would have duplicated the gate and left the
provider blind. Files: new `records.py` (§4.1 FT-M/N/O/P), `licensing.py` (§7.1 classes, §4.3/§5.4
union), `bridge.py` (admit → select → envelope → dial); `resolve.py`, `admission.py`,
`manifest.py`, `config.py`, `app.py` extended. `registry/src/server.ts` now serves the
`selectFinetune` verb it always advertised. 172 trainer tests + 141 registry tests; `make check`
exit 0.

### Learnings for future iterations
- **`describeRegistry().verbs` was advertising a verb the HTTP surface did not serve.**
  `selectFinetune` existed only as a TypeScript `import`, so the Python bridge could not reach the
  one implementation of the FT-K precedence. Worth grepping the other `describe()` verb lists
  against the routes before assuming a capability is reachable over the wire.
- **A record file is the one input the offline resolver must NOT stand in for.** Its
  `dataset-jsonl-header` rides the manifest precisely so egress/license/cardinality resolve
  without a fetch (FT-N/FT-P). `default_resolver` now reads the real declared facts for
  `records[]` while still being an honest stand-in for packs and assets — mixing the two would
  have made the gate's own numbers fictional.
- **License is NOT an admission gate at the provider (KFT §4.3) — resist making it one.** The
  first cut refused any input with no license class, which fires on every job the offline resolver
  produces (it cannot know the base model's license). The gate that IS reachable and correct is
  the *header's* declared class: the producer controls it, the schema requires it, and the §5.4
  union the output inherits is unanswerable without it. Deployment allowlists stay opt-in.
- **`dataset.header` predates `dataset.records[]`.** A lone header with no records is the
  pre-0.4.0 degenerate form (the existing `valid_text_job` fixture is one). Rejecting it would
  have broken every prior story's tests for no contract reason; it is accepted, and its axes still
  count toward the aggregate.
- **The koine job schema closes the manifest (`additionalProperties: false`) and has no
  `provider` field**, so KFT §8's "a job MAY name a target provider" cannot ride the body. It is a
  `submit(provider=…)` argument / `X-Agora-Provider` header instead — a routing preference, not
  part of what is being asked for. Worth revisiting as a koine edit rather than inventing a field.
- **`vite-node`, not `node`, for any generator that reaches `registry.ts`** (parameter property →
  `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX` under Node's strip-only loader — the same constraint
  `examples/participant-starter` keeps the SDK under). And `vite-node` does not leave the script
  path in `process.argv`, so an entry-point guard silently never fires: use an explicit env flag
  (`AGORA_CAPTURE=1`).
- **A second cross-language fixture landed**: `registry/src/fixtures/finetune-selection.json`,
  read by `registry/src/select.test.ts` AND `trainer/tests/test_registry_selection.py`. Same
  discipline as `trainer.manifest.json` — regenerate, never hand-edit. Changing the trainer's
  manifest now invalidates BOTH fixtures.
- **Adding an endpoint to the trainer manifest is a three-file edit**: `manifest.py`,
  `test_manifest.py`'s "advertises no endpoint it does not serve" assertion, and the regenerated
  `registry/src/fixtures/trainer.manifest.json` (whose regeneration command is in the failure
  message).
